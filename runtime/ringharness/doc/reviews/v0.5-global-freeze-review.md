2026-09-11。承接v0.4 FG01/FG02，范围为当前10份编号文档、导航、Schema、规则样例与冻结工具；不是应用实现审计或运行验收。原v0.3/v0.4快照不变。

## 全局检查

| 链路 | 复核结果 | 运行边界 |
|---|---|---|
| MEA角色与宿主 | Planner零工具；受信生命周期与模型工具分离；Auditor独立验证 | 实际身份/沙箱待验收 |
| 调度、租约与恢复 | 旧attempt不复活；原效果核对；信任锁在scope锁之前 | PG多连接/真实停止待验收 |
| 证据→run→Audit | FG01新增同事务Assessment、全量枚举、VerificationObligation；提交者不能过滤有效反证 | run/Audit窗口kill待验收 |
| 三态与最终屏障 | 有效FAIL优先；无正式审计、未结算义务、信任阻断不能PASS；当前FINALIZE宿主可提交但其动作已结算 | Task/Goal假DONE计数须为0 |
| Skill与来源失效 | FG02先封锁项目，再遍历Skill/Context/候选/发布；自动撤销，CAS解锁 | 并发dispatch/失效、跨Goal传播待验收 |
| 预算与收尾 | 封锁不关闭回执/停止/有界安全对账；维护不授予模型新推理或工程动作 | 预算耗尽保持阻断待验收 |
| 版本与内容摘要 | 新Content v3/29类；v1/v2历史读取；事件v1独立；规范化链接指向v3 | 生产标准库与领域准入待实现 |
| API与前端 | 87条唯一方法/路径；TrustState及撤销原因、判定/正式审计分别呈现 | 生成客户端/实际接口一致性待验收 |
| 存储与运维 | 判定/引用/outbox原子；传播job有游标、deadline与revision，不能旧job解锁新决定 | 备份/重启/对象仓一致性待验收 |
| 测试与发布 | 原T/AT/E/100h门槛保留；新增FG反例及固定规则样例 | 无运行通过声明 |

## 静态与规则证据

`python3 doc/tools/check_spec.py --allow-pending-freeze`通过：11份Markdown、29类Content、87条路由、10有效/11非法哈希向量；Python/JavaScript对46字段与事件样例结论一致，12个验证器预设结果与17个单槽判定/信任准入/解锁样例通过。

这些规则样例不是应用domain实现，也不证明线程、数据库或模型正确。信任失效后仍有历史运行事实，但不允许新的可信导出或受影响Skill行动；不将历史DONE改成重新运行。

## 冻结判定

FG01/FG02在规格层关闭。本轮限定范围未发现新的未关闭P0/P1规格阻塞项，可以冻结v0.5作为开发基线；不能据此承诺不存在未知缺陷。冻结清单/快照/receipt位于releases/v0.5，文件完整性另由`--verify-freeze`校验。应用源码、迁移、真实E2E、100小时验收与应用发布仍待完成。
