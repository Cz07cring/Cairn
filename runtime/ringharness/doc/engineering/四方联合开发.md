## 3. 交接与验收流（Hermes 的介入点）

1. **立项**（Hermes）：写清批次边界、依赖、验收 seam；未立项不得动工。
2. **认领**（owner）：补全 §2 字段，写进账本 / Issue。
3. **实现**（owner）：在**自己的 worktree** 完成，禁止多方共写同一 worktree 的同一文件。
4. **自证**（owner）：PR 正文贴「本批验证」——命令 + 输出摘要 + 退出码。
5. **审计**（reviewed_by）：查三权隔离、假 DONE、重复副作用、文档一致性。
6. **验收**（Hermes）：按 §4 复跑，独立于 owner 自报；**通过才宣布 done**。
7. **合并**（merged_by）：按 Hermes 裁定的顺序合并；契约变更方先跑 `generate_contracts.py` 确认无 drift。

## 4. Hermes 只认这些证据

- **认**：真实命令 + 真实输出摘要 + 退出码；缺环境时写明 **skip 原因**。
- **不认**：自报「已通过」「应该没问题」；fixture 冒充模型结果；模型成功 / shell exit 0 / Activity SUCCEEDED / Workflow COMPLETED / 前端按钮态当作 Goal DONE；未登记字节当作 PASS。
- 证据不足即**退回**，状态记 `blocked`，不记 `done`。
- 验收需跑全量 `test_local` 时，Hermes 先在 Issue 公告并等 Cursor 让位——同一时刻只允许一方使用共享开发容器库。

## 5. 红线（任何一方触发即停）

1. 禁假 DONE：DONE 只走 Kernel + 固定 VerificationProfile + 屏障。
2. 禁双调度：Temporal 已接管，不得为「没人值守」静默回退 LEGACY。
3. 契约单向：`doc/contracts` → `contracts` → OpenAPI → TS 客户端；禁反推、禁手改 `generated.ts`。
4. PLAN activation 工具集必须为空；工具路径由 Kernel/Broker 再鉴权。
5. 配置不可变：策略/模型/验证配置版本行，禁 UPDATE/DELETE；`BLOCKED` 信任态不接受新配置。
6. 冻结字节：`doc/releases/**`、`.runtime/**`、v0.5 冻结文档不可改。
7. 密钥、私钥、库密码、token 不入库、不进 Issue/PR、不进前端。
8. 不诚实覆盖：OpenAPI 与 `implementation-coverage.json` 只反映已实现路由，禁成功 stub。
9. 集成测用独立测试库/桶，永不碰生产或其他业务库。
