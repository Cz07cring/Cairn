## 3. 证据用词口径（采纳 §4.2，并补一条禁令）

| 词 | 只可在何时使用 |
|---|---|
| `observed` | 某个日志/API/状态**已观察**，但尚未证明整体正确 |
| `verified` | 指定场景按固定输入与**可复现方式**通过 |
| `accepted` | 命令/消息已被可靠持久层受理 |
| `completed` | 局部执行单元完成，**不代表** Task/Goal DONE |
| `delivered` | 结果成功交付给指定接收者，**必须有 ack** |
| `done` | **只能是** Kernel 在固定 VerificationProfile 与最终屏障上的业务裁决 |

**补充禁令（Hermes 增）**：`accepted`、`completed`、`delivered` **不得**在账本、PR、Issue 或验收结论中替代 `done`；`verified` 不得用于未经独立复跑的自报结果。前三者一旦被当成完成态使用，等同假 DONE。

## 5. 一并生效的边界（采纳 §8，不改写）

- 增加 API/字段/状态 → 先改 `doc/contracts` 与 `doc/05`，再迁移、代码、OpenAPI、TS 客户端。
- 改变 Temporal Workflow 命令序列 → 先有 patch/version 门与旧 history replay 测试。
- 增加工具并发 → 先冻结调用级分类合同与结果归属，再改 Runner/Broker。
- 增加自动恢复 → 先有 expiry/max-attempt/unattended 政策与**过期反例**。
- 新增"完成"类状态 → 必须证明它**不会绕过** Kernel 的 DONE 裁决。

## 6. 采纳后立即生效的门禁（写入 AGENTS §7.1）

以下七条（附录 §6）**今日生效**，与既有红线并列：

1. 上游官方 AgentLoop 未真实调用前，不宣称"Harness 接入完成"。
2. ToolResult 没有回到下一轮模型前，不宣称"多轮工具循环完成"。
3. 独立 Runner/Broker 身份下未完成 `PREPARED → DISPATCHED → SUCCEEDED + evidence` 前，不宣称"受控工具 live 通路完成"。
4. prepare/receipt 窗口 crash 后无法定位原 `logical_step_id/effect_id` 时，**不开启自动恢复副作用**。
5. `UNKNOWN`、缺 evidence、未确认 Stop 或隔离资源存在时，**不开启后续工具准入或最终屏障**。
6. 未完成调用级并发分类前，保持同 activation/workspace 工具串行。
7. 并发实现**不能先于**串行闭环、恢复不重复副作用和 typed timeout 的证据。
