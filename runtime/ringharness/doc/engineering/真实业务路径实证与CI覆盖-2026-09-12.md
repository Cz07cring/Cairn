> 本文记录一条**实测**结论与随之补上的覆盖缺口。所有数字均来自本机实跑，附命令与凭据位置。
> 口径提示（AGENTS 规则 13/14）：本文只声明 **observed / verified**，不声明 `done` ——
> `done` 只能是 Kernel 在固定 VerificationProfile 与最终屏障上的业务裁决。

## 一、结论：真实业务全链已跑通（真实模型自主决定工具顺序）

命令（可用 `scripts/run_business_e2e.sh live N` 复现）：

```bash
RING_E2E4_LIVE_CHAT=1 RING_HARNESS_CHECKOUT=<pin 检出> \
  uv run pytest \
  "tests/e2e/test_e2e4_official_loop_to_goal_done.py::test_e2e4_run_activation_live_diagnose_seal_then_goal_done" -q
```

实测：**连跑 3 次全过**（14.55s / 17.31s / 13.59s / 18.44s），非一次侥幸。

该用例产出的 `run-summary.json`（证据文件，位于 pytest tmp 的 run artifacts 下）关键字段：

| 字段 | 值 | 含义 |
|---|---|---|
| `driver` | `deepseek-official-agent-loop` | 驱动者是**真实模型**（DeepSeek），不是桩 |
| `scripted_order` | `false` | **非脚本化**：工具顺序不由测试给定 |
| `chat_driven_order` | `true` | 由模型对话轮次驱动 |
| `injected_fsm` | `false` | **未注入 FSM** 兜底 |
| `prompt_nudge` | `weak_goal_no_tool_order` | 弱提示：**不规定工具顺序** |
| `done_authority` | `control_kernel_finalization` | DONE 只由 Kernel 判定 |
| `marks_goal_done_by_loop` | `false` | 循环自己**没有**写 DONE（三权分立成立） |

`trail` 覆盖全业务链：

```
run_activation_live_diagnose_fix_seal → seal_candidate_via_loop_broker
  → materialize_holdout → execute_outcome_candidate → broker_auditor_run_tests
  → audit_pass_task_done → integrate → broker_finalize_run_tests → finalize_goal_done
```

即：**目标 → 计划 → 执行（官方 AgentLoop，模型自主 read→test→fix→test→seal）→ 独立 Broker
→ 封存候选 → 审计 → 集成 → 最终屏障 → Kernel 判 DONE**，全部真实进程、真实模型。

## 二、补齐的缺口：这条路径此前在 CI 中**零覆盖**

`tests/e2e/**` 的业务全链用例需要上游 Harness checkout；未设置 `RING_HARNESS_CHECKOUT` 时
它们按自身守卫 **skip**。而 `foundation.yml` 与 `temporal-path.yml` 都没有拉取 Harness ——
于是**最重要的业务路径在 CI 中既不跑也不红**，只是安静地跳过。

这与本仓反复出现的一类缺陷同族：**skip 被误读为通过**。

本次补齐（`temporal-path.yml`，Hermes 持有的编排 CI）：

- 上游 Harness 为**公开仓库的钉扎归档**（实测 `HTTP 200`），故 CI 可自行拉取：
  `scripts/pull_harness_pin.sh <pin>` → `scripts/build_harness_agent_loop.sh`；
- 新增步骤「拉取并构建钉扎 Harness」+「真实业务路径测试（E2E；可见 skip 明细）」；
- **失败关闭**：Harness 缺失/未构建时脚本以非零码退出，不静默降级；
- live 变体在 CI 中**仍然 skip**（需模型凭据）—— 不假装它跑过，故同时新增
  `scripts/run_business_e2e.sh` 供有凭据的环境复现。

本地按 CI 同参数预演（不设 `RING_E2E4_LIVE_CHAT`）：

```
tests/e2e/  →  29 passed, 1 skipped in 60.14s
（唯一 skip = live_chat 变体，按设计失败关闭）
```

即：**29 条业务路径用从此进入 CI**（此前全部 skip）。

### 关于 #3 的接口约定（供 Cursor 实现 Kernel 半边）

设计依据 `doc/v0.6/01-开发文档.md:59`：运行时 GoalReview 由 **Workflow 持久计时器/进度事件**触发，
**Kernel 用触发键去重**创建 `AUDIT(target=GOAL_REVIEW)`；快照绑定合同与计划版本；
**复盘频率、停滞阈值、最大重规划次数必须配置并纳入预算，不得无限复盘**。

按此，编排侧将调用一个 Kernel 活动（名称与参数待定，建议）：

```
request_goal_review(goal_id: str, trigger_key: str, review_seq: int) -> dict
```

- `trigger_key` 需**幂等去重**（建议 `f"{goal_id}:{review_seq}"`）；
- 返回须包含「是否已存在同键」（去重命中不算失败）；
- Kernel 侧负责：频率/停滞阈值/最大复盘次数**校验与预算扣减**；
  超预算须**失败关闭**并回报原因，不得静默跳过。

编排侧实现（周期计时器 + patch 门 + 演进登记）我会在 Kernel 活动落地后接线 ——
**刻意不先做**：没有写入方的旋钮等于不可达（AGENTS 硬规则 17），
先接线会造出「已实现但没人能用」的假能力。
