# E2E开发调试文档

> V1开发规格v0.5。下面是待实现脚本/部署契约，当前不可据此直接启动应用。[02](02-测试文档.md)定义测试门槛。

## 1. 两条链路

fake链路：浏览器→API/Kernel→PG Activity调度→隔离Runner→fake模型→Broker真实沙箱动作→Ledger→独立审计→屏障/最终状态→ReadModel。

live链路使用相同应用和工具，仅切到实际本地Qwen。fake保证可复现，live验证真实tool calling/context/取消/恢复；两者不能互替。外部效果统一用测试服务，云模型只在明确测试授权下开放。

PLAN 阶段专项调试：fake/live 均注入只读、Skill、shell 和委派工具请求，观察 adapter 拒绝及 Kernel/Broker 的403/ROLE_TOOL_FORBIDDEN；核对工具请求数、StepRecord/EffectIntent新增数为0，无文件访问或出站工具请求。再提交合法采集任务，确认仅独立 EXECUTE activation 产生工具记录，结果经 ContextCompiler 返回 Planner。模型推理调用及宿主续租单独计数，不算 Planner 工具；验证过程与T09对应，当前待执行。

## 3. Fixture与故障点

固定最小Git仓库：重连缺陷、单元测试、浏览器页、独立holdout、受保护基线。Executor只改允许src；真实验收在seal后的CandidateManifest副本上运行，不能用其自报stdout代替。

模型场景：invalid_json/tool_call_wrong_type/context_overflow/stream_disconnect/429/503/same_error_loop。系统场景：plan_before_publish_kill、runner_kill、stale_writer、long_upload、db_unavailable、artifact_interrupted、effect_response_lost、barrier_dispatch_race、sse_gap。每场景记录固定seed与故障窗口。

## 4. E2E用例

## 5. 调试入口与定位顺序

先固定run_id/时间，再关联goal/task/activity/attempt/effect/receipt/command。区分浏览器过期、用户命令等待、活动未领取、模型/工具失败、证据来源失败、最终屏障等待。

| 现象 | 查哪里 | 处理 |
|---|---|---|
| 点击一直转圈 | /commands?idempotency_key或/commands/:id | 只用原key/body核对，不另建命令 |
| PLANNING无Task | /goals/:id/activities中的PLAN | 查lease/checkpoint，不因无Task判丢工作 |
| READY无人领取 | Activity依赖、budget_scope、资源quarantine、Runner能力 | 不手改状态；核对claim前置条件 |
| 上传时异常失租 | heartbeat renewal_seq/expiry与state_revision | 续租不能排在上传后或要求业务CAS |
| 接管后重复动作 | /activities/:id/steps、/effects/:id、approval consumption | 先停新准入，核对原effect，禁止换ID补跑 |
| 旧Runner结果被拒 | effect_receipts inbox、producer身份 | 保存真实回执并由当前Kernel对账，不放行旧状态提交 |
| 最终验收一直等待 | barrier/in_flight/UNKNOWN/容器状态 | 显示具体等待原因，不跳过排空 |
| hash正确仍未过审 | source/manifest/profile/criterion verdict | 内容完整性不等于来源或正确性 |
| UI状态倒退 | latest_seq/entity_state_revision/旧请求回包 | 修投影合并，不改后端迎合UI |
| 只有live失败 | model snapshot、角色模板、工具JSON/取消 | 最小provider probe后定位，不盲改全Prompt |

拟定只读scripts/inspect_run.py --run-id与scripts/export_evidence.py --run-id --output；两者输出脱敏诊断和manifest，不能内置UPDATE status='DONE'修复路径。

```sql
-- 表落地后由驱动绑定参数；诊断使用只读凭据
SELECT id, kind, status, state_revision, current_attempt_id
FROM activities WHERE goal_id = :goal_id ORDER BY created_at;
SELECT activity_id, id, fencing_epoch, lease_expires_at, renewal_seq, status
FROM activity_attempts WHERE activity_id = :activity_id ORDER BY started_at;
SELECT id, logical_step_id, status, payload_digest, external_ref
FROM effects WHERE goal_id = :goal_id ORDER BY created_at;
SELECT write_epoch, status, in_flight_engineering, unknown_effects
FROM finalization_barriers WHERE goal_id = :goal_id ORDER BY created_at;
SELECT seq, event_id, type, payload
FROM events WHERE goal_id = :goal_id ORDER BY seq;
```

查不到/依赖不可达记unknown，不能推断外部动作没有发生。

## 6. 复现包与真实运行

Playwright trace保留失败，截图/视频/run日志隔离；Trace Viewer能检查动作、DOM和网络，仍需结合后端证据。[官方说明](https://playwright.dev/docs/trace-viewer)

包包含manifest、JUnit、trace、关键截图、console/network、request/command ID、事件、Activity/attempt、Step/effect/receipt/审批消费、预算/屏障、Candidate/ReleaseManifest、来源/信任配置、上游/应用版本和seed。凭据脱敏后副本另算hash，原始材料按ACL保存。

live先probe身份、tool calls、流结束/中断、角色/模板、上下文和中文；/models成功不证明工具成功。再跑E01/E02/E05/E06/E10与专项，最后T22。100h记录器独立于浏览器，被测版本变化不能拼接时长冒称同一版本通过。

结束先固定证据/核对hash与来源→输出未决effect/资源→清run专属数据→记清理结果。fake/live/chaos/100h四项状态分别汇报，未执行不标通过。

## v0.5全局故障验收

FG01/T05/T09/E06：固定候选，A失败run已登记后kill且无Audit；B接管提交通过run并省略A，最终仍FAIL。run登记事务前后分别kill：前者义务OPEN，后者assessment完整；均不能假DONE。迟到结果、来源失效、待核对输入和正式Audit缺失分别验证，不能用模型文本替代。

FG02/T13/T20/E10：已ACTIVE Skill的验收来源失效，与activate/dispatch/finalization并发。决定先提交则零新准入，先发动作保留核对；通知丢失仍拒调用；跨Goal/SkillSet/Context/候选传播，旧发布INVALIDATED。传播进程kill/预算耗尽保持BLOCKED；旧job不能解锁新revision；解锁不复活REVOKED。核对实际DB顺序、容器、网络动作和UI。
