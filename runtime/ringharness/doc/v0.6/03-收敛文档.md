# 收敛文档：业务裁决与工作流完成分离

> v0.6 / DESIGN_REVISION · 2026-09-11。Temporal 技术栈修订，尚未实现、未冻结、未完成运行验收。本文与链接的 v0.5 基线合读：本文明确列出的替换规则优先，其余领域、安全及验收要求全部继承；不把历史“未开始”状态当作当前代码状态。

继承基线：[03-收敛文档.md](../03-收敛文档.md)。

## 完成公式

Goal DONE = 当前合同全部必要标准覆盖 + 固定候选与版本匹配 + 独立可信验证记录及Assessment满足阈值 + 无未结验证义务 + 无未核对效果/旧写权限/资源 + 最终屏障合法 + Kernel同事务发布ReleaseManifest。

Temporal Workflow COMPLETED仅表示编排函数结束；FAILED/TIMED_OUT/TERMINATED也不自动等于业务FAILED/CANCELLED。Workflow只在Kernel已给出合法终态或明确移交持久恢复责任后退出。未知终止由恢复程序发现并关闭准入，不以Temporal状态覆盖业务事实。

## 三态

PASS/FAIL/INSUFFICIENT仍是证据验收三态，不能用Temporal success/error/cancel映射。Auditor提交提案，Kernel验证run→producer/attempt→候选→profile/layer/round→义务→可信回执及Assessment。仅存在VerificationRun外键不证明验收正确。任一必要FAIL不能被其他PASS掩盖；缺证据为INSUFFICIENT；旧版本不能推进新合同。

## 最终屏障

Kernel关闭工程准入并递增write_epoch → Workflow调度排空/核对 → 未确认停止仍隔离 → Ledger封存最终候选 → 独立FINALIZE → Kernel复核最新信任版本、义务和全部标准 → DONE/ReleaseManifest。每个跨进程步骤都有稳定命令ID和幂等回执，外部IO不持PG锁。

## 运行中收敛

GoalReview是周期诊断，不贡献PASS。Workflow以持久计时器/里程碑请求运行快照；Critic针对偏离、无进展、重复失败给证据与建议；Planner只提出计划调整。重规划/换attempt/Continue-As-New均不清零Goal总预算、lineage重试计数和停止义务。
