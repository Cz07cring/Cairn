## 启动与隔离

专用业务PG、Temporal Server及独立存储、S3、测试身份源 → 两套服务各自迁移 → Kernel API/Relay → Python Workflow Worker → TS Runner/受信Broker → Web。一个开发单机可以承载这些进程，但数据库、账号、namespace与工作目录隔离；Temporal Server不得读写业务表，Runner不得持业务DB凭据。

新增compose/启动脚本仍待实现，不给未存在的脚本编造成功命令。真实模型使用现场确认的本地Qwen；禁止读取生产环境、默认切云或在本轮启动服务。Temporal开发服务器只用于本机测试，不作为生产HA或100h数据持久性证明。

## 两条验收链

fake：真实浏览器/API/PG/Temporal/Runner/Broker/S3，只有模型输出可控。live：相同链路替换为真实Harness与本地Qwen，不允许测试辅助buildPlan生成计划。

E01—E10原断言保留；每次动作记录业务ID和Temporal执行引用。先证明一次规划→真实文件动作→独立验证→最终候选，再跑故障窗口。不能只验证Cordis boot或模型端口可连。

## 排查顺序

| 症状 | 检查 | 不允许的绕过 |
|---|---|---|
| START后未运行 | PG命令/outbox、Relay、绑定、Workflow是否存在、task queue能力 | 重建Goal或换幂等键盲发 |
| 有Workflow无执行 | Kernel准入、预算、信任、资源隔离、Runner poll | 手动改READY或删租约 |
| 任务完成但UI未更新 | PG outcome回执、journal/outbox、SSE水位 | 以Temporal COMPLETED填DONE |
| 取消后进程仍在 | StopRequest/Receipt、进程树、resource_instance、隔离账 | 释放资源后直接新跑 |
| 重放报不确定性 | 历史、Worker构建版本、Workflow版本分支 | 跳过重放检查强行部署 |
| Temporal不可用 | 保持待派发/只读，恢复后对账再投递 | 自动启用旧PG dispatcher |

## 故障脚本与证据要求

独立controller注入Relay崩溃、Activity完成丢失、Worker kill、模型停机、PG/S3/Temporal断连及宿主重启。所有脚本仅操作本run资源；时间窗口、随机seed、目标进程与原始观测持久保存在被杀进程外。

除原复现包，新增Temporal history、版本映射、Continue-As-New链、outbox重复投递记录。模型输出/密钥不写入history；大日志用对象引用。真实100h不使用时间快进，测试服务器快进只能用于计时器单测。
