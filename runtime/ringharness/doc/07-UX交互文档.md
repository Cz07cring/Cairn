# UX 交互文档

> V1开发规格v0.5，尚无页面或用户测试。实现协议见[04](04-前端文档.md)、[05](05-API接口文档.md)。

## 1. 信息优先级

让用户随时知道：在做什么、什么已被独立验证、是否需我处理、还能在何种预算和权限下继续。业务进度、活动恢复、用户命令、外部效果分别展示；不会要求用户理解内部epoch/事务才会操作。

操作者创建/控制目标，观察者看结果，审批者决定授权，管理员维护策略/模型/Skill/验证配置。三权分立是后台身份和程序规则，不是让用户在三个聊天窗口之间转述。

## 2. 主流程

```text
选择项目→目标与验收标准→固定验证配置→预算/权限/模型
→保存草稿→检查合同→开始→规划→执行→独立审核
→等待在途工作收尾→结果封存与最终验收→已完成
                         ↘证据不足/失败→恢复/重规划/需处理
```

草稿不执行；开始前一次展示允许行动、模型/数据范围和总预算。已授权范围内后续动作自动推进，不逐工具要求确认。验收标准必须可观察，系统可建议但要在开始前呈现固定合同。没有真实估计依据时不显示精确完成时间。

## 3. 状态文案

| 后端状态/对象 | 展示 | 用户含义 |
|---|---|---|
| Goal DRAFT/PLANNING | 草稿/规划中 | 前者未执行；后者可在活动页看到规划，即使还无Task |
| Task PENDING/READY | 等待前置任务/等待执行 | 可查看依赖和资源 |
| RUNNING | 执行中 | 展示最近有效进展，不只心跳 |
| VERIFYING | 审核中 | 候选存在，独立验证尚未完成 |
| Task RETRYING/STALE/RECOVERING | 准备重试/执行连接失效/恢复中 | 正在换方法或核对旧执行者 |
| BLOCKED | 需要处理/等待条件 | 区分需用户处理与系统可自动恢复 |
| PAUSING/PAUSED | 暂停中/已暂停 | 保存和收尾完成后才称已暂停 |
| CANCELLING/CANCELLED | 取消中/已取消 | 既有外部效果不会自动撤回 |
| FAILED/DONE | 未能完成/已完成 | 前者保留部分结果；后者有固定验收证据 |
| Command ACCEPTED/RUNNING | 已受理/处理中 | 仅用户请求进度，不等于业务完成 |
| Effect UNKNOWN | 操作结果待核对 | 不能确认已发生与否，系统停止盲目重试 |
| Barrier DRAINING/SEALED | 等待工作收尾/结果已封存，正在验收 | 前者仍可能有先前发出的外部工作；后者禁止工程修改 |
| 数据stale | 状态未更新 | 页面显示最后已确认信息，不能推断后端停止 |

Activity详细状态放诊断/活动时间线，不替换业务Task状态。Task无PAUSED状态，Goal暂停作为附加标记。屏障封存不是完成，hash匹配也不是完成。

## 4. 操作行为

| 操作 | 提交前 | 提交后/错误处理 |
|---|---|---|
| 开始 | 一次检查合同、覆盖标准、预算与授权 | 命令受理后规划；无效字段定位修正 |
| 暂停 | 已授权可逆操作，一键 | 先暂停中，确认写入排空才已暂停 |
| 恢复 | 显示剩余预算、阻塞和配置变化 | 服务端重检，不重置墙钟/重试计数 |
| 取消目标/任务 | 展示范围、依赖、未决效果和已有结果，确认一次 | 取消中；UNKNOWN提供核对入口，不重复提交 |
| 重新规划 | 原因、当前计划版本、影响标准 | 屏障生效时先按流程结束当前验收；不能后台静默改冻结图 |
| 重做任务 | 原失败证据、已用实现轮次、剩余预算 | replacement链接原任务且保留lineage计数 |
| 云升级审批 | subject=MODEL_INVOCATION、数据、provider、费用、有效期与权限差异 | 仅原模型调用+payload获批；工具审批另用subject=EFFECT；一次消费 |
| 未知结果核对 | 原effect、外部引用、可用证据 | 提交核对证据，不把审批当作已发生结果 |
| Skill激活/撤销 | 固定版本与审计记录；撤销说明在途影响 | 未通过验证不能激活；撤销阻止后续动作 |
| 导出证据 | 内部副本或离线可验证包，说明差异 | 后者缺签名配置明确失败，禁止默默降级 |

请求结果未知时显示“正在核对这次请求”，保留原Idempotency-Key；界面不提供改变key来绕过等待的选项。真正再次执行相同业务动作必须有新意图，而不是重新点击原未知效果。

## 5. 证据阅读与三权分立的可见结果

标准卡片显示尚未验证/证据不足/未通过/已验证，点击可追到负责Task、固定VerificationProfile、CandidateManifest、真实命令/输出和Audit。

证据显示三行独立状态：内容摘要匹配、来源已核验、验收结论。原始/脱敏/截断副本标明实际字节范围和来源链接。没有来源验证的hash不显示绿色“成功”。签名通过但测试失败时仍显示“验收未通过”。

Task详情分别标识“执行者提交的候选”和“独立审计结论”，审计不把执行者自述作为来源。最后完成页展示最终集成候选与ReleaseManifest，明确与早期单Task候选的区别。

## 6. 预算、进展与恢复

顶部展示标准已验证数、有效进展时间、待处理数；预算展示已用/预留/上限，未知费用显式待核对。详细页分别展示实现轮次、各层审计次数、活动恢复次数、计划版本；不要用一个“重试次数”让用户误以为审计也算改代码。

恢复时间线：连接失效→旧执行者被隔离→正在核对原操作→找到保存点→继续。未证明隔离或结果时显示核对中，不写“无影响”。DRAINING显示具体待收尾效果，超时说明阻塞原因，不用虚假的百分比。

## 7. 错误与通知

| 场景 | 文案 |
|---|---|
| 网络中断 | 连接中断，当前显示最后确认状态，恢复连接后自动同步。 |
| 命令响应丢失 | 请求结果尚未确认，正在核对这次操作，请勿重复提交。 |
| 版本冲突 | 目标已更新。已保留你的输入，请检查最新状态后再提交。 |
| 模型不可用 | 本地模型暂不可用，系统等待恢复，已保存进度仍可查看。 |
| 证据不足 | 现有证据还不能证明完成，正在补充独立验证。 |
| 屏障等待 | 正在等待已发出的工作结束。全部核对后才会封存结果。 |
| 结果未知 | 无法确认这次外部操作是否完成，系统已停止重复执行。 |
| 预算耗尽 | 剩余额度不足，可查看已完成结果，或调整合同后恢复。 |
| 离线签名不可用 | 当前无法生成离线可验证证据包，可另行选择明确标识的内部副本。 |

通知仅对完成、确定失败、需要用户处理、重大恢复异常；同incident合并，普通心跳/重试不通知。V1应用内通知必需；邮件/聊天外发只有配置和明确授权后启用。

## 8. 无障碍与UX验收

键盘可达、弹窗焦点进入/恢复、非提交中Escape关闭、状态变化温和live region、日志不逐行读屏；状态有文字/图标，不只颜色；支持reduced motion。小屏用表格/列表代替大图，hash可复制与展开。

至少5位目标角色参与者完成：创建可验证目标；找到首次规划活动；区分页面断线/后端恢复；追踪标准证据；暂停并识别真正停止；区分命令受理/效果成功/验收完成；处理过期审批；核对UNKNOWN；理解封存等待；区分内部副本/离线证据。记录成功率、误操作、时间和原话。引发重复副作用、误读DONE或授权不明的问题修复复测，未测试不得声称UX通过。

## 9. 消除细节歧义

“候选计划已保存”与“计划已发布”分开；替换任务时告知哪些后续结果需重新验证。周期巡检显示“发现问题/未发现问题”，不用“验收通过”，也不增加目标已验证标准数。最终审核按每组标准展示证据缺口，不能用一条通过覆盖全部。

规划活动显示“读取准备好的上下文、生成规划”，不能出现可执行工具按钮。暂停到期显示“暂停已超时，等待处理”，不会自动恢复。业务额度耗尽后显示“已停止新工作，正在核对既有操作”；恢复额度耗尽显示“核对尚未完成，需要处理”，保留未知结果。


## 10. MEA交互约束

角色文案：规划者“规划与协调，无工具权限”；执行者“按合同实施”；审计者“独立检查产物”。“新一轮执行”代表独立会话，不代表任务历史丢失；Manager可保留经核验的事实。审计三态仍是已验证、证据不足、证伪，不用“模型很确信”替代。

保护基线被改时说明“验收依据发生变化，本轮结果已隔离”，同时列出未决操作；不要称所有业务数据都已回滚。合法代码变更不会触发该提示。受限审计材料只显示可披露诊断，不能以便于修复为由暴露隐藏答案。


## 11. 三态与完成的文案分离

“审计已完成，结论：证伪”是合法展示；“审计执行失败，尚无有效结论”则属于恢复流程。Manager收到反馈不代表已修复；补证据与新轮修复分别呈现。轨迹清理失败仅显示待清理及处理状态，不称已销毁，也不删除用户可追溯的产物和真实证据。


## 12. v0.5恢复与授权文案

“补证据重审”保留封存结果；“修复后重验”先收尾，再生成新计划和新候选。恢复命令受理不代表旧进程已停止。云模型审批与工程工具审批分别呈现；Planner通过受信宿主推理，不因此拥有任何工具。费用未知显示待核对或按上限保守计账，不显示零费用。


## 13. v0.5验收结果呈现

“补证据后通过”保留之前证据不足记录；“提交结果冲突”与“发现业务失败”分别显示，不能给出覆盖失败按钮。Skill验收不显示不存在的Goal；展示实际验证标准、版本和有效记录。发布后来源失效显示“历史已完成，当前证据已失效”，停止可信导出，不假装项目重新运行。模型审批从创建、决定、撤销到详情统一按subject.type显示，不要求Planner先产生工具effect。

## 14. v0.5失效和未完成验证文案

“验证发现失败，审计记录待完成”与“审计已完成”分别呈现；模型会话崩溃本身不显示任务证伪。“验收依据失效，正在暂停新行动并核对影响”用于项目信任封锁。受影响技能显示“验收证据失效，版本已撤销”，恢复需新版本验证，不给重新接受旧hash按钮。项目恢复不等于旧版本重新有效；已完成发布失效保留历史并显示当前无效。
