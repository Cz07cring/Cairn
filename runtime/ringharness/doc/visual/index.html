三个角色，一条权限边界

MANAGER / PLANNER

规划与管理

读取宿主准备好的上下文，提出任务图、依赖、优先级和重规划建议。

零工具权限，包括只读工具。不能改验收标准或直接写 DONE。
EXECUTOR

实施与提交

按合同使用获准工具，每个新实现轮次使用新会话，提交固定候选。

不能修改受保护验收依据，不能自评后自行放行。
AUDITOR

独立验证

使用独立会话核验固定候选，在隔离临时空间运行批准的验证器。

不能改候选，不读取执行者推理，也不能直接设置完成。

Kernel / Broker / Ledger

受信程序负责授权与执行、证据采集、事务与汇总。模型提交提案，程序按固定规则决定状态。

开发时始终遵守

一套权威状态

业务状态、租约、预算与事件由控制面持久化。会话历史和页面显示不接管业务事实。

固定输入与版本

合同、候选、验证器和 Skill 按版本绑定。变化后重新验证，不用旧通过结果证明新版本。

验证随实现推进

每个工作包验证对应不变量；W07负责综合验收，测试工作不全部推迟到最后。

EVIDENCE & ACCEPTANCE

“完成”必须有依据。

Hash 核对字节，可信采集核对来源，独立验证核对标准。三者共同组成验收链。

证据怎样形成

① 真实动作Broker 采集命令、环境和回执
② 原始工件保存实际字节并计算 SHA256
③ 可信判定Run 与 Assessment 同事务保存
④ 独立审计绑定候选、标准与验证器
⑤ 程序汇总全集核对，禁止挑选通过结果

三态验收

缺证据与证伪不是同一回事。

已验证
PASS

所有必要项获得有效通过证据，正式审计齐备，且没有未决验证与安全阻断。

证据不足
INSUFFICIENT

证据缺失、来源未核对、审计未完成或环境不可用。补证据，不伪装成功。

证伪
FAIL

有效反证表明标准未满足。同一候选的有效失败不能被后来的通过结果覆盖。

最后一道：目标收敛

关闭工程准入 → 排空在途动作 → 封存最终候选 → 独立全局验收 → 事务写入 DONE

子任务全部通过，并不自动等于目标完成。集成产物要重新验收；未知效果、未结算验证义务或信任封锁都会阻止完成。
