# 编排侧接缝审计（E2E-3/4 预备）：一个被推翻的假设 + 一个可达性确认

> 日期：2026-09-12 | 作者：Hermes | 依据：代码实测，非推断
> 范围：`packages/orchestration/**`（我的路径）与 Kernel 的活动调度链

## 一、被推翻的假设（诚实记录）

**我的假设**：工作流的准入入口只有 `admit_plan_action` / `admit_execute_action`
（`kernel_activities._admit_kind_action` 仅支持 `PLAN`/`EXECUTE`，见
`temporal_workflows.py:240`）。若 `AUDIT`/`INTEGRATE`/`FINALIZE` 活动需要「准入」才可被领取，
而工作流又只准入 PLAN/EXECUTE，那么任务在 EXECUTE 之后就会**静默永久卡住** ——
与 Issue #24（放弃裁决未持久化）同族的第二个缺口。

**实测结论：假设不成立。** 全仓所有活动类型创建时**直接就是 `status='READY'`**，
worker 按 `kind` 领取即可（`claims.py:659` `WHERE status='READY' AND kind = ANY(:kinds)`），
**无需编排准入**：

| 活动类型 | 创建处 | 初始状态 |
|---|---|---|
| `AUDIT` / `FINALIZE` | `finalization.py:241` | `'READY'` |
| `INTEGRATE` | `integrate.py:127` | `'READY'` |
| 工程类（PLAN/EXECUTE 等） | `plans.py:355`、`task_commands.py:441` | `'READY'` |
| 其他（skill_validate / memory_index / obligations / evidence_export / probe） | 各处 `INSERT INTO activities` | 均 `'READY'` |

且 Kernel 内部以**事件链**自我推进（无需编排在场）：

```
EXECUTE 完成 → AUDIT 活动（READY）
  → submit_audit_outcome 全 PASS → Task DONE → maybe_schedule_integrate（audits.py:282）
  → INTEGRATE 活动（READY）→ 成功 → open_finalization_barrier（integrate.py:258）
  → Goal→VERIFYING + 屏障 + FINALIZE 活动（READY）
  → submit_finalize_outcome → Goal DONE + ReleaseManifest
```

**因此编排层只负责 PLAN/EXECUTE 的准入与观察，其后由 Kernel 链 + worker 领取推进 —— 这是设计，不是缺口。**
我按上一轮的怀疑去查，查完确认不成立，如实记录以免后续重复怀疑。

## 二、可达性确认：Goal DONE 链**已存在且被测试覆盖**

`tests/integration/test_finalization.py::_goal_done_with_release`（第 393 行）跑通完整快乐路径，
断言：

```python
assert goal_done["status"] == "DONE"
assert goal_done["barrier"]["status"] == "RELEASED"
assert goal_done["release_manifest_id"] is not None
```

实测：`tests/integration/test_trust_invalidation.py` → **13 passed**（其中 691 行断言 DONE 后失效语义）。

**关键性质**：该助手通过 **HTTP claims + outcome 提交**直接驱动
（`_claim_finalize_lease` → 领取 FINALIZE 租约 → 提交 outcome），
**不经过 Temporal 工作流**。即：

- **Kernel 级 DONE 链：已成立、已测试。**
- **E2E-4 的增量价值**在于：让同一条 DONE 链由**真实 Harness（官方 AgentLoop）驱动的执行**产生
  候选与证据，而不是由测试助手直接构造 —— 而不是「让 DONE 变得可达」。

这个区分对台账很重要：`FINALIZATION` 类问题不应被登记为「DONE 不可达」，
而应登记为「真实驱动路径尚未接通」。
