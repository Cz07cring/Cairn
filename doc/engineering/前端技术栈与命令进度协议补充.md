## 1. 技术选择与职责

| 层 | 确定的选择 | 边界 |
|---|---|---|
| 控制服务 | Python / FastAPI / Pydantic | Kernel 与 ReadModel；唯一业务事务入口 |
| Broker 与证据 | Python / S3 兼容仓 / Git | 可信采集、工具准入、证据来源与版本 |
| 数据与迁移 | PostgreSQL / Alembic | 业务状态及约束；pgvector 仅辅助检索 |
| Harness 接入 | TypeScript ESM / Node / 官方 adapter | 固定上游版本，不能另立调度与状态权威 |
| 用户界面 | React / TypeScript / Vite | 客户端工作台；使用生成 API client |
| 服务端数据缓存 | TanStack Query | 查询、失效、加载/错误状态；不重复建立全局任务状态副本 |
| 局部交互 | React state / reducer / context | 表单、选中步骤、面板和日志跟随；跨页筛选使用 URL |
| 实时状态 | HTTP / 既有 SSE | SSE 仍仅失效通知；命令输出走独立分段查询 |
| 样式 | CSS Modules + CSS 自定义属性设计令牌 | 共享颜色、间距、字号、状态与响应式规则 |
| 测试 | pytest / Vitest / React Testing Library / Playwright | 规则、组件交互和真实浏览器全链路 |

新增前端库选择以本补充为开发决策；具体版本尚未锁定。W01 验证 Node/Harness、React/Query、构建与测试工具兼容后，使用 uv.lock/pnpm-lock.yaml 精确固定传递依赖，保存版本矩阵。路由统一使用 React Router 的客户端模式；不增加第二个前端服务端业务层。UI 组件库不作为阻塞项，原生控件加共享组件先满足语义与无障碍。

TanStack Query 的查询失效/重取符合其服务端数据管理定位；局部状态采用 React 的既有机制。参考：[TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)、[React 状态管理](https://react.dev/learn/managing-state)。

## 2. 前端代码归属

```text
apps/web/src/
├── app/                 # router、providers、登录态和 AppShell
├── features/
│   ├── goals/           # 创建、列表、合同确认
│   ├── execution/       # 活动时间线、命令与调用详情
│   ├── approvals/       # 授权详情及提交用户意图
│   ├── evidence/        # 候选、标准、审计、交付
│   └── onboarding/      # 演示、空状态、上下文帮助
├── shared/
│   ├── api/             # 生成客户端包装、错误映射、查询键
│   ├── realtime/        # 每 Goal 唯一 SSE 订阅与重同步
│   ├── ui/              # 表单、弹窗、标签、分页、可访问展开控件
│   └── styles/          # tokens、基础样式
└── test/                # 组件级辅助与无敏感信息 fixture
```

features 不直接 fetch，不连接 Harness 或对象仓内部地址。shared/api 包装 packages/api-client，统一 CSRF、请求 ID、幂等键、401 与错误处理。查询缓存键包含项目、对象、表示版本、过滤条件和权限代次；退出/切项目/权限变化清除敏感缓存并取消旧请求。React Query 自动重试仅用于有界可重试读取；写命令不由框架默认重试，按原幂等/结果查询协议恢复。

业务状态只从权威 API 读取。CommandOperation SUCCEEDED、shell exit_code=0、临时流结束都不能设置 Goal DONE。页面对按钮禁用不能替代后端鉴权。

## 3. 工作台与用户习惯

左栏：项目、最近目标、待我处理、历史交付。中栏：目标概览与执行时间线，计划图是可切换标签。右栏：选中动作的说明、命令、输出、变更与证据。小于 768px 时详情进入可返回的独立视图，URL 保留目标、选中步骤与标签；用户不需要在多个聊天窗口转述。

首次进入无任务时提供示例与“创建目标”；再次进入恢复最近有权访问的目标。创建步骤先写目标，再确认可观察标准、固定验证配置、完整预算和允许范围，最后保存草稿或启动；草稿保存成功须有服务端回执。表单错误定位到字段，409 保留输入，禁止自动放宽权限/降低标准。

顶部固定回答：当前在做什么、最近有效进展、是否需要我、预算状态。待处理列表只列需要决策的问题，自动恢复归执行状态。用户查看日志时，不抢焦点、不自动展开新卡、不把视口拖回底部；提供“有新输出/继续跟随”。完成页先给交付物与变更摘要，再给验收依据，诊断 ID 可展开复制。

## 4. 命令卡片与状态来源

“命令卡”在产品文案中指工具执行；用户的暂停/取消等请求在 API 中仍是 CommandOperation，二者不能混名建表。

| 显示项 | 来源 | 缺失时 |
|---|---|---|
| 用途、工具 | StepResource.purpose/tool_ref | 不猜测 shell 命令 |
| 脱敏命令 | Broker 实际请求的安全展示表示 | 显示不可披露，不回退 RAW |
| 排队/审批/执行/核对状态 | effect、approval、可信采集事实 | 显示待确认；禁用无授权操作 |
| 开始/结束/退出码 | 可信执行观察与 TrustedReceipt | null 显示未知；退出码 0 仍非 Goal 通过 |
| 最后输出时间、分段日志 | §6 安全输出表示 | 无输出不等于卡死 |
| 测试进度 | 批准解析器从实际工具输出采集 | 显示不定量状态，不估算百分比 |
| 文件差异、测试报告、截图 | 固定候选和 Artifact 引用 | 未生成/受限/已清理分别显示 |

进度对象 ToolProgress={kind:INDETERMINATE/COUNT,completed:int|null,total:int|null,unit:string|null,observed_at:Timestamp,parser_ref:string|null,source_segment_id:uuid|null}。COUNT 要求批准 parser_ref、来源 segment 和 0≤completed≤total、total>0；否则只能 INDETERMINATE。进度是工具报告的观察，不能构成验收证明。总数变化可使百分比回退，UI 提示范围更新，不强制单调伪造；不跨 attempt 拼接计数。

## 5. 执行查询 API 草案

以下新路径以 /api/v1 为前缀，沿用 v0.5 认证、项目 ACL、JSON envelope 和错误结构，全部只读。它们尚未在当前 87 条冻结路由中实现或生成。

| GET 路径 | 参数 | data |
|---|---|---|
| /activities/{activity_id}/execution-timeline | cursor?,limit=50，最大200 | TimelineItem[] |
| /effects/{effect_id}/execution-view | 无 | ToolExecutionView |
| /activities/{activity_id}/attempts/{attempt_id}/runtime-view | 无 | RuntimeView |
| /effects/{effect_id}/output-segments | representation_id?,after_cursor?,limit_bytes=65536，最大262144 | OutputPage |

TimelineItem={id:uuid,activity_id:uuid,attempt_id:uuid|null,parent_item_id:uuid|null,kind:MODEL/TOOL/CHECKPOINT/AUDIT/RECOVERY,source_type:string,source_id:uuid,observed_at:Timestamp,recorded_at:Timestamp,summary:string,source_revision:string|null}。id 根据来源身份稳定生成；新修订更新同项，不增重复卡。按 recorded_at+id 稳定分页，第一请求固定快照高水位、meta 返回 snapshot_at 与 next_cursor；新记录通过显式刷新开始新分页。不同活动可能并发，同活动仍遵守 v0.5 顺序步骤规则。summary 为脱敏事实摘要或标明模型说明，不包含思维链。

ToolExecutionView={effect_id:uuid,activity_id:uuid,origin_attempt_id:uuid,observing_attempt_id:uuid|null,logical_step_id:uuid,purpose:string,tool_ref:string,effect_status:EffectStatus,command_display:string|null,display_redacted:bool,started_at:Timestamp|null,finished_at:Timestamp|null,exit_code:int|null,signal:string|null,timed_out:bool|null,progress:ToolProgress|null,last_output_at:Timestamp|null,approval_id:uuid|null,receipt_ids:uuid[],artifact_ids:uuid[],representation_id:uuid|null,observed_at:Timestamp}。EffectStatus 沿用05，不创建另一套权威 FSM。origin_attempt 不因接管改写；observing_attempt 仅标当前采集者，exit_code 等结果来自已经受理的可信回执，未核对结果不伪装已确认。

RuntimeView={activity_id:uuid,attempt_id:uuid,harness_commit:string,adapter_version:string,profile_digest:Digest,session_generation:int,session_state:ACTIVE/CLOSED/UNAVAILABLE,model_snapshot:ModelSnapshot|null,skill_versions:SkillVersionRef[],observed_at:Timestamp}。模型与 Skill 复用原 attempt 对应类型，不重复定义；内容来自启动前固定的 Runner 运行清单，不读取当前默认配置代替历史事实。UNAVAILABLE 不等于从未执行；不公开原始 session_ref 或会话管理 URL。此只读视图及运行清单为新增实现项，不能凭现有 checkpoint.session_ref 推导所有字段。

## 6. 输出分页、脱敏和中断

OutputPage={representation_id:uuid,segments:OutputSegment[],next_cursor:string|null,has_more:bool,stream_state:OPEN/CLOSED/UNAVAILABLE,redaction_version:string,observed_at:Timestamp}。

OutputSegment={id:uuid,seq:string,channel:STDOUT/STDERR/SYSTEM,text:string,observed_at:Timestamp,source_attempt_id:uuid,truncated:bool}。seq 是表示内单调递增十进制字符串；stdout/stderr 交错是采集顺序，不声称真实跨管道因果顺序。分段保持合法 UTF-8，不能截断字符；limit_bytes 限制返回 text 的 UTF-8 字节总量。next_cursor 为本次扫描后续读位置（即使暂时无新输出也可返回），has_more 只表示当前高水位下是否仍有数据。OPEN 且无新输出返回200空 segments，不能返回 CLOSED；终态查询 CLOSED 也不能被 UI 当验收通过。

初次无 representation_id 时由服务端按权限选择脱敏表示，随后客户端固定该 ID 和游标。游标绑定主体权限范围、项目、effect、表示、位置及快照策略，必须防篡改，不接受客户端任意对象仓偏移。每次读重新鉴权；每个表示独立去重，不混合不同表示分段。表示更新或游标过期返回410 OUTPUT_CURSOR_EXPIRED，前端清除原展示、标明历史缺口并重新获取，不无声拼接。无权访问遵守原404/403隐藏策略。

Broker 的 stdout/stderr 先经过受信分段脱敏器，才进入可读 spool。脱敏器必须处理跨 chunk 的敏感串、ANSI/控制字符与日志注入；未处理完整的尾部暂不发布。未知或失败不得回退 RAW 输出。终态字节封存为 Ledger artifact，动态 spool 与不可变工件分离。读取路径不持有业务写权限；输出缺失、磁盘不足、截断均单独报告，不丢弃最终 TrustedReceipt。

每 effect 的输出大小、保留时间和每项目并发读取额度必须有部署上限；达到上限停止保存更多输出并记录 truncated，不停止计费/回执核对。保护 RAW 若必须保留，置于独立受限存储，不进入普通页面或导出默认范围。临时模型说明与 shell 输出分开，前者不纳入永久命令证据。

可见且展开的运行命令每2秒读取一次，单页面最多2个活跃输出读取；隐藏/折叠停止轮询，重新展开续读。错误指数退避至30秒，401/403停止并清缓存，429遵守 Retry-After。返回 CLOSED 且 has_more=false 后停止轮询。Activity 列表依既有 SSE 失效重读，不新增逐行日志 SSE。UI DOM最多1000行，搜索明确为“已加载输出”，全量搜索未实现前不宣称覆盖历史。

## 7. 安全控制与用户操作

本轮只新增只读观察 API。暂停、取消、重审、审批仍走05既有端点；终端面板不提供任意输入或重放命令。对于 UNKNOWN，唯一引导是核对既有操作；新意图需经原业务流程。命令展示做纯文本转义，复制前说明已脱敏；文件/SVG/HTML 工件受隔离，不执行日志中的链接或指令。

官方 Harness UI 默认不开放；如未来开放仅限经过能力验证的诊断身份，必须证明不能绕过 Kernel/Broker、预算、角色隔离及会话清理。当前应用不依赖其页面接口。

## 8. 验收与交付顺序

| 编号 | 必须验证 | 判失败条件 |
|---|---|---|
| UI02-01 | 干净安装、类型检查、锁文件与生成代码无漂移 | 隐式依赖或任意旧客户端仍可编译通过不兼容合同 |
| UI02-02 | 新建目标→命令受理→PLAN→工具→审计→交付真实链路 | 前端自行设置完成或无 Task 时误报未启动 |
| UI02-03 | stdout/stderr 分片、UTF-8、重复、空轮询、关闭后续读 | 丢字/重复行/无新输出误判停止 |
| UI02-04 | 跨分片密钥、控制字符、HTML、跨项目/权限撤销 | 原始敏感内容泄漏或执行不可信输出 |
| UI02-05 | 接管、旧回执、游标失效、输出截断 | 合并不同尝试进度或隐藏缺口 |
| UI02-06 | COUNT/未知总数/变化总数/模型自报进度 | 伪造百分比或将进度作为验收证明 |
| UI02-07 | 滚动、返回、筛选刷新、移动端、键盘与焦点 | 抢滚动、丢草稿或操作不可达 |
| UI02-08 | 隐藏页、卸载、429、大日志、并发订阅 | 无界内存/轮询，或超原04性能门槛 |
