## 2. 业务场景（不是假任务）

套利台价差计算模块 `arb/spread.py` 有两处会导致**真金白银**判断错误的缺陷：

| # | 缺陷 | 为什么是钱的问题 |
|---|---|---|
| 1 | `spread_bps` 返回**原始价差**（`ask - bid`），未按参考价归一化到 bps | 不同价位的标的无法横向比价；高价合约的价差被系统性高估 |
| 2 | `cross_contract_bps` 把**不同计价单位**的合约价格直接相减 | 这正是本次约 **7× 假价差**的成因，不是合约乘数 |

真实数据来源：币安 USDT-M 永续 `fapi/v1/ticker/bookTicker` 与 `fapi/v1/exchangeInfo`
（`SKHYNIXUSDT` 与 `SKHYUSDT` 同经济敞口但计价单位不同，`contractSize` 均为 `null`）。
行情在系统外拉取后以快照入仓；**无出网时拒绝以占位数据继续**（见 §6 第 8 条）。

## 3. 端到端链路（一次投递，五类活动）

投递一次 `ENSURE_WORKFLOW`，其后全部由工作流自推进（`advance-on-ready`），
**没有任何人工触发第二次**。

| 活动 | 结果 | 目标 | 时刻 (UTC) |
|---|---|---|---|
| PLAN | SUCCEEDED | GOAL_PLAN | 13:34:37 |
| EXECUTE | SUCCEEDED | TASK_WORK | 13:34:59 |
| AUDIT | SUCCEEDED | CANDIDATE | 13:35:58 |
| INTEGRATE | SUCCEEDED | INTEGRATION | 13:36:02 |
| FINALIZE | SUCCEEDED | CANDIDATE | 13:36:03 |

- Goal 创建 `13:34:36.839` → 判 DONE `13:36:07.567` = **90.7 秒**
- 模型：`deepseek-v4-pro`（`provider_ref=deepseek:api`），PLAN 1 次 + EXECUTE 7 次，**全部 SUCCEEDED**
- 受控工具 effect **8 个，全部 `exit_code=0`**：ENGINEERING 6（read×3 / write / run_tests / seal）
  + VERIFICATION 2（AUDIT 与 FINALIZE 各一次独立 run_tests）
- 交付清单 `release_manifest = 2be3a6cb…`，屏障 `RELEASED`（`write_epoch=2`）

### 三权分立落在实处

- **执行方**（Runner/Broker）只能提交意图与回执，**不能**判 DONE，也不能直接写业务库；
- **验收方**（AUDIT / FINALIZE）跑的是**独立套件**，且校验器身份与候选摘要在活动创建时
  由 Kernel **冻结进分配**，执行方读不到也改不了；
- **判定方**（Kernel）在固定 `VerificationProfile` + 最终屏障上裁决 ——
  本次两条准则：`MECHANICAL` **PASS** + `GLOBAL` **PASS**。

## 4. 交付物与独立验证

执行方交出的实现（节选）：

```python
def spread_bps(bid: float, ask: float) -> float:
    return (ask - bid) / ask * 10_000          # 按参考价归一化到 bps

def cross_contract_bps(price_a, price_b, face_value_a, face_value_b,
                       quote_asset_a, quote_asset_b) -> float:
    if None in (face_value_a, face_value_b, quote_asset_a, quote_asset_b):
        raise ValueError(...)                   # 缺面值/计价单位 ⇒ 拒绝
    if quote_asset_a != quote_asset_b:
        raise ValueError("不同计价单位的合约价格不能直接比较")
    notional_a, notional_b = price_a * face_value_a, price_b * face_value_b
    if notional_b == 0:
        raise ValueError("基准名义价值 notional_b 不能为零")
    return (notional_a - notional_b) / notional_b * 10_000
```

**两套测试分工（这是「独立验收」的关键）**：

| 套件 | 可见性 | 作用 |
|---|---|---|
| `tests/test_spread.py` | 执行方**可读可写** | 给方向：表达完整契约口径（含算例） |
| `tests_hidden/test_spread_hidden.py` | 执行方**不可见**（`protected_paths`） | 防敷衍：换另一份盘口、量纲校验、`ask=0` 边界、**计价单位不匹配必须拒绝**、**面值必须真参与换算** |

审计套件 `pytest -q tests/ tests_hidden/` → **10 passed**（可见 4 + 隐藏 6）。

**隐藏测试曾被实测确认为真门禁**：把缺陷版实现放回去，隐藏测试 **6 项全红**；换回正确实现全绿。
不做这一步，「独立验证」就只是个说法。

## 5. 系统在这条链上正确挡下过一次不合格交付

价值不在「跑通」，而在**它挡住了错的东西**：

- 第 1 轮：模型只做面值换算、**未归一化到 bps**，可见测试仍全过 → **审计 FAIL**，Goal 不 DONE；
- 第 2 轮：模型分母口径与契约不一致 → **审计 FAIL**；
- 修正契约表述（补算例）与可见测试（表达口径）后，第 3 轮交付出合格实现 → 双 PASS → DONE。

即：**可见测试过 ≠ 任务完成**；判定权在 Kernel，执行方无法自证。

## 6. 本轮修掉的根因（这些是「跑不通」的真实原因）

| # | 根因 | 症状 | 修法 |
|---|---|---|---|
| 1 | **EXECUTE 完成回执从不上报** | 活动永停 `RUNNING`，Temporal 侧早已 `COMPLETED` | 新增 `executeOutcomeSubmit.ts`，在两条执行通路收尾提交回执 |
| 2 | **就绪活动无推进** | PLAN 成功后 EXECUTE 停 `READY` 20+ 分钟无人动 | `advance-on-ready`：有实质进展且仍有就绪工作 ⇒ Continue-As-New |
| 3 | **Runner 越权派发（竞态）** | 执行 6 步"运气好"成功，验收 `run_tests` 永停 `DISPATCHED`、零回执 | Runner **只 prepare**；派发唯一归 Broker（取件队列只认 `PREPARED/AUTHORIZED`） |
| 4 | **Broker 令牌过期后永久 401 空转** | 托管循环用同一张过期令牌反复重启，永不恢复 | 启动器加 `--refresh-bearer`；托管循环重启前续铸；Runner 按激活重读令牌文件 |
| 5 | **新增活动未注册** | 工作流直接 FAILED（`not registered on this worker`） | 登记 `admit_runtime_action` 到 `KERNEL_ACTIVITIES` |
| 6 | **审计分配缺 `subject_digest` / `verifier_digest`** | 审计器抛 `MISSING_SUBJECT_DIGEST` / `VERIFIER_DIGEST_FETCH_FAILED: 403` | Kernel 在**创建时**把两项身份冻结进分配（最小权限，不放宽公共路由） |
| 7 | **鉴权头漏补 `Bearer `**（6 处同族） | 逐个撞 `401 请先登录`，每修一处暴露下一处 | 收口为单一 `authHeader.ts`（该缺陷类第 5 次出现） |
| 8 | **工作区铺设依赖出网** | 出网不可用时沿用上轮**不合格交付**与新 Goal 起跑，审计连续 FAIL 且与模型无关 | 工作区重置与行情拉取解耦（行情回退仍保持"缺出网不写占位数据"的诚实分支） |

第 3 条最贵：它是**竞态**，两条路径上分别呈现"成功"与"永卡"，极易被误判为"验收功能没做"。
第 8 条最隐蔽：它是**失败静默**——`if live:` 让整个工作区重置被行情拉取连坐。

### 顺带记录的判断失误（自我纠正）

我第一版隐藏测试**未在契约中写明分母口径**，却断言了一个具体分母。模型选了另一个同样合理的
口径 —— 那是**我的规格缺陷**，不是模型的问题。修正做法：把口径与算例写进任务书，
并让可见测试表达它，隐藏测试只保留「可见测试没覆盖的面」。

## 8. 诚实边界（未覆盖 / 不宣称）

1. **C1 的「产出报告」这一半未被验收实际校验**。C1 描述要求写 `reports/` 下的分析报告，
   但 `MECHANICAL` 层只跑 `run_tests`，而套件不检查报告存在性 —— 本次交付**只改了代码、未产出报告**，
   C1 仍判 PASS。这是**验收口径的盲点**，不是模型违约。
2. `GLOBAL` 层的通过来自同一条 `run_tests` 证据，**语义层（SEMANTIC/ADVERSARIAL）未启用**。
3. 本次为**单任务 Goal**；多任务 DAG、任务间依赖与并行调度未在此场景验证。
4. 未验证：长跑（>50 分钟，即跨令牌续铸周期以上）下的完整 Goal；崩溃恢复不重复副作用；
   并发工具调用（当前保持同 activation 串行）。
5. 本地全量 `pytest` 仍受共用开发库残留状态影响（本仓已知）：报失败前须与 `origin/main` 对照。
6. 本文**不**宣称「无人值守系统已完备」，只宣称：**上述这一条业务链路已端到端跑通并留证**。
