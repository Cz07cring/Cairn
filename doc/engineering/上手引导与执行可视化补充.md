# 上手引导与执行可视化补充

> U01，基于 v0.5 的前端补充设计，未纳入原冻结包。doc/visual/index.html 提供交互原型，所有执行数据是示例；应用 API、Harness 事件映射和用户验收均待实现。本补充不改变原 MEA 权限、三态汇总与完成规则。

## 1. 首次使用与信息架构

首页提供“第一次使用，从这里开始”，引导顺序为目标与可观察标准、权限和预算确认、执行路径、验收依据。默认中文，以“正在做什么、是否需要我、下一步是什么”为信息优先级；内部 ID 放展开诊断区。

原型使用预填代码修复目标，校验必填、空白输入和时长范围。填写只保存在内存，刷新清除；不收集真实密钥。真实应用仍须完整创建合同：每条标准绑定固定验证配置，预算包括 token/费用/时间/工具等约束，不能把原型的单个时长字段当完整预算。实际草稿保存与启动分开，成功提示依权威 CommandOperation 和 Goal 状态。

## 2. 执行详情与数据来源

| 视图 | 数据来源与关联 | 展示规则 |
|---|---|---|
| 目标/任务/活动 | 既有 Goal/Task/Activity 查询 | 首次 PLAN 无 Task 仍可见 |
| 执行尝试 | Activity attempts、checkpoint | 明确接管前后尝试与版本，不覆盖历史 |
| 模型调用 | model-invocations，activity_id/producer_attempt_id | 实际 provider/model 与批准范围；不暴露原始输入或思维链 |
| 工具路径 | activities 的 steps → effects → receipt/工件 | 权限请求、发出、结果核对分开，UNKNOWN 不提供直接重试 |
| Skill 与 Harness 配置 | 受信 Runner 的固定版本记录及批准上下文引用 | API 尚缺精确展示合同，不从当前设置猜测历史版本 |
| 候选与审计 | CandidateManifest、VerificationRun、AuditAggregation | 具体候选对应标准，可信判定、正式审计与 DONE 分开 |

统一时间线由 ReadModel 聚合已持久事实，Harness live stream 仅为临时观察，不改变任务状态。列表去重以事件/资源身份为准，时间戳只用于展示；并发步骤按父子关系分组，不伪造严格因果顺序。重连按 v0.5 snapshot/SSE 规则重新读取，UI 不从 Harness 日志恢复权威 effect。

实现前必须补齐并另升协议版本的项目：统一时间线分页 DTO/路由、Harness 版本与会话 generation 的安全查询字段、工具调用与 effect 的关联映射、脱敏日志分段读取、候选文件差异与截图索引。现有 v0.5 API 已覆盖部分底层对象，但本文件不能被当作这些新 API 已冻结。W06 在接口评审通过后生成客户端，不在页面临时拼接未定义接口。

## 3. 输出查看与双界面边界

输出分为日志、文件变更、测试报告、浏览器截图与证据引用；标识来源、候选、产生时间、是否截断/脱敏。HTML/SVG 不能直接在同源有权限页面执行。长日志按段分页，权限变化清缓存，隐藏 holdout 与审计推理不向 Executor 或普通浏览者披露。

本系统 UI 拆成三面（2026-09-14 裁定）：**Hatchet 风格管理面**（目标/注意力/执行记录/健康）、**DeepSeek Harness Web 执行面**（对话与工具轨迹，固定上游 SHA）、**Ringharness 可信治理面**（合同、租约、Effect、审批、屏障；DONE 只经 Kernel+VerificationProfile）。管理面所有写动作仍走 Kernel 授权与幂等协议。

驾驶舱 `#run-live`（「执行面 · Harness」）提供固定 pin 深链入口（`apps/web/src/harnessWebPin.ts` + `HarnessWebExecutionPanel`），本机用 `scripts/serve_harness_web.sh` 起官方 `dsh web`；裸 `:3080` 会 401，须用终端打印的带 token URL（可写入 `VITE_RING_HARNESS_WEB_URL`）。同页下方仍是 Kernel 只读时间线，不编造私有推理。

执行面默认应对用户开放为「受控激活工作台」，但**不得**用裸 iframe 绕过 Broker：须先验证认证、角色 ACL、工具执行与配置修改限制、临时会话清理；不能保证只读或无法阻止绕过 Broker 时禁用嵌入，仅保留深链/诊断入口。拥有页面访问权限不等于有工具执行权限；Harness session 完成 ≠ Goal DONE。

## 4. 异常引导

| 场景 | 用户能理解的说明 | 可提供操作 |
|---|---|---|
| 等待授权 | 准确动作、目标、数据类别、费用与有效期 | 查看完整审批；缺必要字段不能批准 |
| 工具结果未知 | 原操作可能已发生，正在核对 | 看核对进度/提交允许的核对证据，不重复执行 |
| 页面断线 | 当前是最后确认状态，后台情况未知 | 重连并重取快照，不推断任务停止 |
| 证据不足 | 缺哪些必要项、系统是否在自动补证 | 查看缺项与受控重审入口 |
| 有效失败 | 哪条标准被反证、对应候选和证据 | 受控修复流程，不能覆盖失败或降低标准 |
| 完成 | 固定交付物、全标准审计、最终清单 | 查看和按权限导出真实工件 |

演示页没有实际审批、暂停、重试或导出按钮；切换场景不冒充命令响应。真实产品的暂停/取消按原 v0.5 的受理、排空、确认状态呈现。

## 5. 验收要求

U01-01：新用户可填写示例，空白/非法时长被阻止，返回能保留输入，刷新无敏感持久化。
U01-02：从任务追到具体工具请求、结果与候选；真实测试必须对照后端 IDs，不能用原型通过。
U01-03：旧 attempt 接管和重复通知不产生重复执行卡，历史记录与版本仍能查询。
U01-04：断线不显示已停止；UNKNOWN 不出现直接重执行；缺审批事实不能批准。
U01-05：模型/工具成功不显示 Goal DONE；缺正式审计、有效 FAIL 或信任阻断均不能显示完成。
U01-06：官方 Web 入口不能绕过 Kernel/Broker；未验证限制则不开放。
U01-07：390/768/1280 宽度、键盘、弹窗焦点、长输出、脱敏与跨项目权限回归。
U01-08：至少 5 位目标用户完成原 UX 文档任务，并新增“定位失败工具、理解接管、找到交付依据”；记录时间、成功率与误操作。造成重复副作用或误读完成的问题必须修复复测。

当前证据仅能证明静态原型交互；以上真实链路和用户测试尚未通过。工程化目录补充 E01 与本 UX 补充 U01 相互独立，不改变原冻结版本。
