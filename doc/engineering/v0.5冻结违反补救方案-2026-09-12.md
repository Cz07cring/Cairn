## 三、根因：AGENTS 自身存在规则冲突

| 条款 | 要求 |
|---|---|
| **AGENTS §2** | 「`doc/` 编号文档与 `doc/contracts/` 是**设计权威**；**改协议须同步文档**/schema/迁移/生成客户端/测试」 |
| **AGENTS §7.1 规则 6** | 「`.runtime/`、**v0.5 冻结字节**与 `doc/releases/` **任何一方不得改**」 |

`doc/05-API接口文档.md` **同时**落在两条规则之下：
- 它是「编号文档 = 设计权威」（§2 要求随实现同步）；
- 它又在 `doc/releases/v0.5/manifest.json` 的冻结清单里（§7.1 规则 6 禁止改动）。

**11 个批次的行为，是在执行 §2；被 §7.1 规则 6 判红。** 这不是纪律问题，是规范冲突。

## 四、为什么不建议 revert `doc/05`

1. 会删除 11 个批次累积的真实 API 记录（含 Issue #24 端点、`GOAL_ENGINEERING_CLOSED` 等已实现语义）；
2. 与 §2「改协议须同步文档」直接冲突 —— revert 后**规范将落后于实现**，而 §2 正是要求二者同步；
3. 这些事实没有更合适的现成载体：`doc/v0.6/01` 是「下一版设计」，`doc/engineering/**` 是工程补充，
   都不是 API 字段/路由的**权威**位置（§2 明定 `doc/05` 才是指定路由权威）。

| 方案 | 做法 | 代价 / 风险 |

且 §2 已明定它是指定路由权威，与「冻结字节」的角色本就冲突。

**但这属治理决定，我不单方面执行** —— 修改 `doc/releases/**` 全在 AGENTS 明令禁止之列（规则 6）。
