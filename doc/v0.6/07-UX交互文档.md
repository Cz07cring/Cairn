# UX交互文档：任务管理习惯优先

> v0.6 / DESIGN_REVISION · 2026-09-11。Temporal 技术栈修订，尚未实现、未冻结、未完成运行验收。本文与链接的 v0.5 基线合读：本文明确列出的替换规则优先，其余领域、安全及验收要求全部继承；不把历史“未开始”状态当作当前代码状态。

继承基线：[07-UX交互文档.md](../07-UX交互文档.md)。

用户仍围绕“目标→执行→问题→交付”操作，不需要学习Temporal。默认页面展示当前在做什么、最近有效产物、等待谁、如何继续；技术诊断展开后才显示workflow/run/attempt。

| 实际事实 | 用户文案 | 可用操作 |
|---|---|---|
| PG已受理，尚未派发 | 已收到，等待执行服务 | 查看原因、取消；不重复创建 |
| Temporal故障，业务事实保留 | 执行服务暂不可用，进度已保存 | 查看最近确认时间；恢复后继续 |
| 重投同逻辑动作 | 正在恢复连接/核对结果 | 查看历史，不增加“完成任务数” |
| 已请求停机，无确认 | 正在停止，等待确认 | 查看未决动作与超时原因 |
| 旧进程失联 | 正在隔离并核对资源 | 不显示“资源已释放” |
| 方向偏离 | 复盘发现问题，待调整计划 | 看证据、计划差异；标准不自动降低 |
| 所有必要标准通过且Kernel DONE | 已验收并交付 | 查看逐项证据与下载交付 |
| Workflow已结束但Goal非终态 | 运行中断，等待恢复核对 | 显示业务阻塞原因，不给完成庆祝 |

审批绑定原意图/摘要/有效期；费用和权限变化必须重新审批。前端刷新或双标签不产生第二个命令。暂停后恢复沿原Goal继续，保留费用、轮次、证据和审计拒绝历史。

上手流程：检查执行服务→选择项目→填写目标与验收标准→预算/模型/Skill→确认合同→启动→查看执行时间线→处理问题→验收交付。缺配置时给明确可修复原因；查看与保存草稿可以独立于执行服务可用性。

三态始终按证据展示“已验证 / 证据不足 / 验证失败”，周期诊断另列INFO/WARN/BLOCKER。不得把模型思考原文当作必需进度；提供可公开的动作说明、状态、结果摘要与工具日志。

继承原无障碍、中文错误、键盘导航、焦点恢复、空态/错误态/陈旧态分离要求；真实浏览器验收而非截图即通过。
